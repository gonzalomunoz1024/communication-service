## 5. What could not be exercised, and why

- **F-61 behind a real OpenShift Route / HAProxy** — no cluster. Exercised instead behind a minimal SSE-aware reverse proxy (`scripts/rp.js`) in HOLD mode (reconnects held until the backend is back, so the service's answer to the resumed stream is observed). The non-HOLD path (an immediate 502 during the restart) was not run; the EventSource specification and the observed reaction to the 500 (connection failed, readyState 2, no retry) imply the same stuck outcome.
- **SIGTERM / rolling restart from the browser's point of view** — the backend's graceful shutdown (`server.shutdown=graceful`, 30 s) refuses new connections immediately but keeps open streams alive, then aborts them ("Graceful shutdown aborted with one or more requests still active", `backend-sigterm-with-open-sse-scenario.txt`); through the dev proxy the browser never saw the cut, so the SIGKILL scenario stands in for it.
- **Browsers other than Chromium** (Playwright's bundled Chromium only; Firefox/WebKit are not installed). EventSource give-up behaviour on non-200 answers is specified identically for all browsers.
- **Screen-reader behaviour** — only roles, names, keyboard paths and axe were checked.
- **A real OS theme switch** — emulated with `emulateMedia({ colorScheme })`.
- **Backend-only clauses of shared rows** (full F-07 rule list, F-14 ordering at scale, F-27 id regex → 400 and Swagger exemption, F-09 `PUT` attach) — Backend Verifier.
- **Visual regression** — no baseline images beyond the README screenshots; screenshots were not used as evidence (no visual-only problem was found).

Processes I left running for the orchestrator (all mine, safe to stop; the shared stack was never touched): own backend `java … --server.port=18093` (db `fe_reconnect`), Vite `:3011` (`COMM_BACKEND=http://127.0.0.1:18093`), front `node rp.js 3041 18093` (`:3041`), `python3 -m http.server 3027` (cross-origin build).
