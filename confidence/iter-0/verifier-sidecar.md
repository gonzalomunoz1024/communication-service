## 5. Not exercised in this sandbox, and why

- **Real Pod / real SCC admission / `oc apply --dry-run=server`**: no OpenShift and `kind` cannot start pod sandboxes here (nested `runc` fails, see `environment.md`). Pod behaviour was emulated with Docker containers sharing one network namespace (a `hold` container owns the namespace like Kubernetes' pause container, the app and the sidecar join it), the sidecar running as arbitrary UIDs with read-only root, all capabilities dropped and `no-new-privileges`. What Docker cannot emulate: the kubelet's liveness restart itself (emulated with `docker kill`/`start`), native-sidecar start/stop ordering, `fieldRef` env resolution, SCC mutation of the pod spec.
- **UBI base images**: `registry.access.redhat.com` is blocked; the image was built from the unmodified `sidecar/Dockerfile` with `golang:1.24`+UBI CA path as the builder and distroless static as the runtime base. The UBI CA bundle location at runtime (`/etc/pki/tls/certs/ca-bundle.crt`) and the "~10 MB" claim are unverified.
- **Dependency / vulnerability scan**: `govulncheck` installed but `vuln.go.dev` is blocked. Mitigating fact: zero third-party modules; exposure is limited to the Go toolchain (image binary built with go1.24.13 from the stand-in builder; the UBI go-toolset would pin its own 1.24 patch level).
- **`/proc/net/tcp6`-only hosts, IPv6-only apps** (`CS_HOST=::1` fallback): not exercised; covered by unit tests `TestListeningPortsMergesTablesAndSkips`.
- **F-46 1-day TTL expiry**: not waited for; `MongoHealthInstanceRepositoryAdapterIT.recordsExpireADayAfterTheyWereLastSeen` is the Backend Verifier's.
- **Long-run resource soak (10 min)**: measured over ~5 min of continuous operation instead (2.7–3.3 MiB RSS).
